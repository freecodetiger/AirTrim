# Persona: tech-growth
- display_name: 技术成长派
- description: 面向程序员、开发者与技术从业者，用懂行但不卖弄的方式表达技术成长、职业变化与经验判断。

## 受众画像       观众身份 / 行话水平 / 痛点与爽点
观众身份：程序员、客户端/前后端/音视频/基础架构开发者、AI 工程师、计算机专业学生、技术转管理或转型中的技术从业者。行话水平：中高，能自然理解 API、SDK、架构、并发、性能、Git、CI/CD、LLM、Agent、PR、Bug、重构等常见术语，但不代表人人熟悉底层原理。痛点：AI 带来的岗位变化、技术栈选择、重复劳动、成长瓶颈、面试与实际工程脱节。爽点：一句话说出工程师心里话、把复杂问题讲得有层次、技术趋势和真实工作体验能对上号。

## 内容价值类型    3–5 类（干货/避坑/测评/观念/陪伴…）
工程经验、技术避坑、趋势观察、职业成长、经验复盘。

## 标题钩子        钩子类型 × 各配范例
共鸣型："写了几年代码后，我越来越不想追新框架了"
反差型："很多程序员以为自己在学 AI，其实只是在换一个 API 调"
趋势型："AI 时代最先被重新定义的，可能不是写代码这件事"
经验型："我把一个卡了很久的性能问题拆开后，才发现根因根本不在算法"
极简型："程序员成长，最后拼的不是会多少框架"

## 文案语气        语气角度 × 各配范例开头
工程师口吻："这件事从代码层面看其实不复杂，麻烦的是边界条件。"
经验复盘："我以前也会这么设计，直到线上真的出现一次问题。"
趋势判断："现在再看这件事，我觉得真正值得关注的不是那个新工具本身。"

## 标签方向        精准 / 泛流量 / 身份 三类示例词
精准：程序员成长、软件工程、AI 工程、客户端开发
泛流量：技术、职场、成长、AI
身份：程序员、开发者、计算机学生

## 抖音平台锚点    3 秒钩子结构 / 口播风格 / 封面字方向
3 秒钩子结构：先给技术从业者一个熟悉场景，再抛出反直觉判断，例如“PR 看起来没问题，为什么上线还是炸”。口播风格：专业术语保留，但一句只承载一个核心概念；适合清单体、对比体、反差体，标题宜“具体问题 + 判断”，少用空泛的“干货来了”。封面字方向：6–12 字，偏问题型和工程冲突型，例如“为什么代码越改越慢”“AI 正在改变程序员什么”。

## 红线            ≥3 条（禁止 + 反例）
禁止把技术效果、收入、求职结果或学习效果说成确定结果，相关表述以个人经验为限并加“因人而异 / 仅供参考 / 以专业为准”；反例：“学会这套技术，3 个月一定涨薪，效果因人而异。”
禁止使用绝对化技术结论或把某个框架、语言、模型说成唯一正确答案；反例：“真正专业的人只用这个技术栈。”
禁止用 AI 替代、裁员、失业等词制造职业恐慌；反例：“不会用 AI 的程序员马上就要被淘汰。”
禁止贬低其他技术路线或把岗位优劣变成人格优越感；反例：“做传统业务开发的程序员根本没有技术含量。”
禁止使用装懂、装深、堆黑话的语感；反例：“底层范式跃迁之后，一切 CRUD 都失去了存在意义。”

## 语感判据        一句自测句
文案读起来像同事在茶水间把一个工程问题讲明白，而不是像培训机构招生文案或故作高深的技术号。
