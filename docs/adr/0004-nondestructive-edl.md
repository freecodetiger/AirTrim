# ADR-0004 · 非破坏性编辑：EditList（EDL）是唯一真相源

- 状态：已接受
- 日期：2026-07-26

## 背景

剪辑类应用最大的信任风险是弄坏用户素材；最大的架构风险是剪辑状态出现多份副本（UI 一份、预览一份、导出一份）后互相漂移。

## 决策

1. **源媒体文件只读，永不修改。**
2. 一次"剪辑" = 一个 `EditList` 值类型（有序、互不重叠的 cut 区间列表）。它是剪辑状态**唯一真相源**；UI、预览、导出都只从它派生不可变快照。
3. **Undo = 快照栈**（`EditSession.history`）。值类型天然免费，不做增量 diff。
4. 分析器产出的 `EditSuggestion` 与 `EditList` 分离：建议不是剪辑；"接受建议"是从 suggestion 合并进 `EditList` 的唯一路径。verbosity 建议必须人工确认（信任模型，见 overview 5.1）。
5. 权威时间用 `CMTime`（有理数）；`Double` 秒只用于 UI 展示，绝不回写。

## 后果

- ✅ 素材绝对安全；崩溃/误操作可恢复；多版本对比免费。
- ✅ 预览与导出保证一致（同一 `EditList` 派生）。
- ✅ `EditList` / 分析器纯值类型，单测直接覆盖。
- ⚠️ 工程纪律要求高：任何"顺手缓存一份区间"的便利做法都是违规（见 ownership-map「最容易翻车的重复状态」）。
